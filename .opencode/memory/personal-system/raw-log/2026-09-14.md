### 5-Why（对"把数据落进 memory"这一动作）

- **Why 1：** 依赖"落库 = 数据被保存"。
- **Why 2（证伪）：** 我存了 **JSON 快照 + CSV 长表**，但**两者的内容都是我手工转录的** ——
  即落库的不是"数据"，是"我抄进 Python 字面量的数字"；若我抄错一位，落库反而**制造了看似权威的错误**。
- **Why 3（反转）：** 真正可复现的做法是**落库存指针**（指向 `example/wif-framework/data/*.json` 的绝对路径 + sha256），
  而非复制数值 —— 复制件会与原件**静默漂移**。
- **Why 4（确认偏误）：** 我想相信"落库了所以安全"，因为这样**这轮工作有个干净收尾**。
- **Why 5（最薄弱）：** 最薄弱的是——**`timing_log.csv` 与 `example/wif-framework/data/*.json` 是两份独立副本**，
  我没有加任何一致性校验；未来两者若不一致，**没有任何机制会发现**。
  （这与本轮反复出现的"同名不同口径"是同一类病：**复制而不绑定**。）

**置信度：** 落库内容正确性 HIGH（数字均来自本轮实测） / **双副本一致性 LOW（无校验机制）**
